# Работа с сайтом через GitHub

## Где находится рабочая версия

Сайт публикуется из ветки `main`, папка `/(root)`. Текущие HTML, CSS, JavaScript, изображения и PDF в этом репозитории — файлы, которые нужно редактировать. Можно использовать редактор GitHub или локальную Git-копию; после изменения в `main` GitHub Pages публикует новую версию. Прежние Python- и PowerShell-генераторы в эту работу не входят.

## Точечная правка существующей страницы

1. Найдите публичный адрес и файл по [карте маршрутов](ROUTES.md). Перед правкой сверьте файл с текущей веткой `main`.
2. Замените только названный текст, ссылку или изображение. Сохраните соседние блоки, показатели и другие кейсы. Если нужен общий элемент, сначала посмотрите [карту компонентов](COMPONENTS.md): не все страницы подключают одни и те же файлы.
3. Проверьте список изменённых файлов и diff. Переименование, удаление файла или раздела, замена всего кейса и массовая пересборка требуют отдельного указания владелицы.
4. Проверьте страницу на широком и мобильном экране, ссылки и изображения. Затем создайте commit с понятным названием и отправьте его в `main`.
5. Откройте публичный URL после публикации и убедитесь, что правка появилась. Сохраните ссылку на commit: по ней можно увидеть точный набор изменений.

Маршрут `/cases/axiom/` сейчас содержит копию кейса 169.ru. Его не нужно автоматически переписывать вместе с `/case-169/`: сначала уточните, должна ли конкретная правка появиться в обеих копиях.

## Новый кейс

Сначала получите текст, изображения, разрешённые к публикации показатели и целевой URL от владелицы. Создайте отдельную папку маршрута с `index.html` и нужными ассетами в репозитории; не копируйте старый кейс целиком без проверки его содержания. Добавьте ссылку в нужной карточке сайта, обновите `ROUTES.md`, проверьте новую страницу и переходы на компьютере и телефоне. Существующие кейсы при этом не удаляйте.

## Файлы, которые не публикуются

Не добавляйте в репозиторий исходные Excel-файлы, `xlsx_dump/`, CSV-выгрузки, рабочие журналы, кэш, ZIP и диагностические копии. Перед отправкой проверьте список новых файлов. Само наличие чисел в кейсе не означает разрешение публиковать рабочую таблицу, из которой они могли быть взяты.

## Старая сборка

При первоначальном создании сайта применялись `assemble.py`, `build_case_169.py`, `assemble_case_169.py`, `build_other_pages_ru.py` и `build_github_package.ps1`. Их входы находятся вне репозитория, часть путей жёстко указывает на временную папку, а повторный запуск может заменить нынешние страницы и вернуть шаблонный Axiom. Для обычных правок эти команды не запускайте. Если когда-нибудь понадобится автоматическая сборка, сначала перенесите её входы в постоянный проект и сравните результат со всеми файлами `main` до публикации.
