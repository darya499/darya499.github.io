# Контекст для следующей работы с сайтом

## Текущая рабочая версия

- Сайт: https://darya499.github.io/
- Репозиторий: https://github.com/darya499/darya499.github.io
- Публикация: ветка `main`, папка `/(root)`.

Сайт обновляется прямой правкой файлов в репозитории и отправкой commit в `main`. Карта файлов — [ROUTES.md](ROUTES.md), порядок работы — [GITHUB-WORKFLOW.md](GITHUB-WORKFLOW.md). Для обычных изменений не требуется возвращаться к прежнему диалогу или временной папке.

## Границы правок

Изменяйте только данные и страницы, которые владелица назвала. Сохраняйте прошлый текст, показатели, изображения и другие кейсы. Перед публикацией сверяйте diff и проверяйте desktop и mobile. Удаление или переименование файлов и разделов требует отдельного указания. Исходный Excel, CSV-выгрузки, кэш и рабочие заметки не добавляются в публичный репозиторий.

На сайте сейчас `/cases/axiom/` повторяет содержимое кейса 169.ru, но это отдельный HTML-файл. Не синхронизируйте их автоматически: сначала определите, относится ли конкретная правка к обеим страницам. Дополнительные кейсы и статьи содержат материалы исходного шаблона; владелица ранее решила оставить их в опубликованном пакете.

## История сборки — только для понимания происхождения файлов

Первую версию главной собирали из `final-body3.html` и `final2.css` через `assemble.py`. Кейс 169.ru собирали через `build_case_169.py` и `assemble_case_169.py`; остальные страницы — через `build_other_pages_ru.py`. `build_github_package.ps1` копировал готовые HTML в пакет GitHub Pages. Эти входы и генераторы не находятся в текущем репозитории и не являются действующим порядком редактирования.

У старых генераторов жёстко задан путь к временной папке. Их повторный запуск может перезаписать последующие исправления в `main`, вернуть старый шаблон на `/cases/axiom/` и подставить заглушки вместо части изображений при недоступном кэше. Автоматическую сборку можно внедрить позднее только отдельной задачей с переносом входов, сравнением всех выходных файлов и визуальной проверкой.
